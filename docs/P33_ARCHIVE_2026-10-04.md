## Contract and transaction

Only a registered local Vanilla active world-set is accepted. The request binds world ID, name, revision, `intent=archive-world-set`, `allowStop`, and UUID Idempotency-Key. No client paths or destination directory are accepted. Unknown/external processes, recovery, stale revision, unsafe links/hardlinks, and separated `_nether`/`_the_end` layouts fail closed. The full world directory includes every existing dimension, player file, saved-data file and other controlled entry.

One writer uses shared OperationService admission. Registered root and physical world directory identities, properties and active reference are rechecked under the instance operation lock. Running managed Java requires explicit allowStop, graceful stop, and stopped/ownership-none verification. Stop may update level.dat; the post-stop revision is recorded separately. A complete pinned guard is copied, flushed and verified against both its manifest and stopped source before any world move.

Schema 5 binds root, world directory dev/inode/birth identity, name/ID/revision, guard ID, archive ID, properties checksum and an exclusive backend-generated `.manager-world-archive-<operationId>` on the server volume. Durable ordering:

1. intent → authorized stop → stop-confirmed → verified pinned guard.
2. Receipt/private destination → archive-ready with destination identity.
3. archive-rename-intent → repeat process/identity/content checks → same-volume complete-tree rename.
4. Verify source absence, archive directory identity, full files/hash and guard → archive-renamed.
5. active-none-intent → persist none plus archiveTransactionId → physically verify state/archive/process → active-none-installed.
6. Commit. Remain stopped; no automatic start, rollback, deletion, retry or copy/delete fallback.

Uncertain results retain all source/archive/guard/journal data and recoveryRequired. Startup verifies immutable root/archive/receipt/guard evidence even for historical confirmed success. Uncertain committed outcomes also require physical none and stopped ownership before confirmation. A none state is accepted only with its physically verified owning transaction; missing/unbound states are not initialized to pending generation. Start/Restart readiness, admission and execution refuse `NO_ACTIVE_WORLD`, including already-running Start no-op and Restart before stop. Empty active inventory and separate safe archive DTOs remain readable; paths/secrets are private.

A later confirmed durable create/import activation can supersede none only with matching registered root/current state/configuration; old archive verification is still mandatory. Existing Create/Import need an active source. This slice adds no none-to-active, archive restore or deletion API; UI explicitly explains manual recovery, while archived data and its pinned guard remain preserved.
