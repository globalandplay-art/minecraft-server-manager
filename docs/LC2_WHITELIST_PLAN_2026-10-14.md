# LC2 whitelist: read-only foundation and controlled-member design

LC2 remains IN PROGRESS. This candidate implements only stored-list reading and its UI; no add/remove endpoint or RCON mutation exists. Remote work PAUSED. No real Minecraft/world/network/system operation is authorized.

## Read-only implemented boundary

Only registered local Vanilla26.3 is admitted; other Vanilla versions, Paper/Fabric/mock and missing registration return unavailable. Require captured registered root identity using existing exact bigint backupDirectoryIdentity before/after reading. Never rebaseline to current filesystem. Instance operation/recovery/external ownership gates remain closed. Files are read only; no member file creation, profile lookup, RCON command, lifecycle action or transaction intent.

Whitelist switches come from saved server.properties; members come from saved whitelist.json. These are distinct data sources and are not claims of effective runtime cache state. Config changes during a combined read reject the snapshot. effectiveEnabled always null; membershipWritable always false. No RCON is required for stored-list reading. Stored UUIDs are format-validated, not account-verified or synthesized.

Whitelist reader:256KiB/1000 rows; strict UTF-8/no BOM/NUL; canonical directory/file, bigint named/opened/after checks, no file hardlink/symlink/root junction; bounded complete reads; close and zero temporary bytes including failure. JSON must be an array of exact name/uuid records. Current name policy ASCII letters/digits/underscore3–16; unsupported names reject the whole snapshot. UUID versions1–5 are normalized to lowercase; duplicate normalized UUIDs or casefolded names reject the whole snapshot. No filtering/truncation followed by success. Valid[] means confirmed empty; missing/corrupt/unsafe means unavailable. Errors return fixed reasons, never file paths/content/exception objects.

GET /api/v1/servers/:serverId/whitelist reuses HTTP authentication and no-store. No mutation route. Whitelist page linked from Properties; explicit stored-source and unverified-runtime labels, manual refresh only, retained old-data notice on error, no add/delete controls or invented defaults.
