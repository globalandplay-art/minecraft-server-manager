## Design and scope

`whitelist-guard-group-scripts.ts` builds one fixed Create or no-replace Move payload for one to eight immutable contiguous backend chunk indices0–63 in a validated UUID guard directory. Manifest is excluded and must remain a separate final publication. It reuses the exact original C# implementation exported from `private-publication-scripts.ts`; all sixteen original single-entry script hash baselines pass.

The entire finite native loop is one proposed admission unit. It is not a claim that JS can revoke individual native instructions after dispatch. The future owning controller must validate/capture every byte/precondition before dispatch, retain actual owner exclusion through actual helper close and refuse every next group/manifest after any failure, cancellation or unknown settlement. Native active-loop death/exclusion proof remains NOT RUN; this component does not implement admission or execute the payload.

Creation returns every full ordered ACL snapshot. Exact creator receipt is owner=user, protected DACL, three full-control Allow ACEs with flags0 and SID multiset current-user/SYSTEM/Administrators. Drift is rejected wholesale, never filtered. General ACL validation is unchanged (its safe64-ACE case remains accepted by the general verifier and intentionally rejected by this narrower creation receipt). Rows/count/order/schema are validated before the persistent SID verifier receives any snapshot. Move receipts contain only exact ordered indices; they do not prove bytes, identities or actual close.

Each compact strict creation snapshot fits1024 ASCII bytes at the conservative184-character SID bound; eight snapshots plus512 framing bytes fit8704, below the unchanged16384-byte writer cap. Complete output is retained. Additional text or stderr remains the existing writer's fail-closed error. No timeout or buffer cap changed.

The command check uses the exact final owner-wrapped UTF16LE/base64 payload and conservative executable quoting, fixed flags/spaces and terminating NUL. It rejects lengths above32767 before future dispatch, with no truncation, transport fallback or group retry/splitting. Windows' limit is documented by [Microsoft CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw). Original root validation's4096-character allowance is not proof that an encoded command fits. New pure measurements show root128: Create26421/Move22937 conservative command characters; root512:29153/25669; root1024 Create rejected and Move29317; root4096 both rejected. These are serialization/bounds facts, not timing or real filesystem support proof. Unicode data can require earlier rejection.
