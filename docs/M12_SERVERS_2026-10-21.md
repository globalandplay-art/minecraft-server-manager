## Actual-page diagnosis

At investigation start both local ports 3000/8080 were unreachable. We cannot
identify which earlier process/build the user had open from that observation.
Verified code defects/conditions were:

- The default development mode is Mock. Servers intentionally hides actual
  registration there, but AppShell incorrectly labelled every mode local.
- Local registration depends on a previously verified Java profile; loading,
  catalog errors and no available profile were not explained clearly.
- There was no registration removal endpoint or button. Removing the final
  instance without retaining its verified Java profile would prevent subsequent
  registration, including after restart.

The top bar now reports the actual mode. Mock Servers explains how to start
local mode. Local Servers shows the existing-directory form and explicit Java
availability. This is not a new arbitrary executable upload/selection API.

## Delivered behavior

Existing preview/save still detects the actual root/JAR/Java, rechecks target
identity and configuration revision, preserves an exact config backup and
publishes atomically. Normal save loads through the existing shared factory;
failed activation remains saved/pending with an error code. Adding never starts
Minecraft or changes the target server files, EULA, ports or world.

`DELETE /api/v1/server-registrations/:serverId` requires strict
`{confirm:true}` and existing local Origin/intent and configured authentication,
CSRF/recent authorization. It serializes against registration and scheduler
changes, takes the existing instance operation lock and checks actual stopped /
no owner / no active operation / no recovery. Pending instances use a temporary
read-only runtime observation to establish stopped status; unknown or unsafe
state is refused rather than discarded.

After publication the selected registry reference, event stream/WebSocket,
active-world memory and performance history are detached, and its observer is
closed. Other instances retain their state. A cleanup failure reports
`unloaded=false`, `restartRequired=true` and a persistent page-level notice;
the removed instance cannot remain operable. Unconfirmed publication preserves
evidence and returns `REGISTRATION_RESULT_UNKNOWN`, never automatic retry.

No server directory, world, player data, mods/plugins, configuration, backup or
historical operation/journal evidence is deleted. The UI explicitly says
“移除服务器”, not delete files. Running, busy, recovery-required and uncertain
instances remain protected. Reusing a removed ID in the same Manager is refused
before save (`REGISTRATION_ID_RETIRED`); use a new ID to preserve old evidence.
Retained history may also prevent hot activation after restart. This is deliberate,
not an invitation to delete history.

Previously verified Java profiles are retained in optional private
`config.json.javaProfiles`, validated for schema and checked against actual
identity/SHA at preview, save and publication. Current adapter profiles appear
first. Tickets bind the selected profile ID, so stale retained profiles cannot
shadow a current revalidated Java at the same path. A stale profile remains
rejected, not silently trusted.

Frontend removal updates the cards and top selector immediately, cancels and
removes instance-bound queries, and replaces the URL with a remaining instance
or an empty state when the selection was removed. Removing a different instance
preserves selection. A named confirmation, busy guard, unknown-result feedback,
keyboard focus containment and explicit refresh path are provided.
