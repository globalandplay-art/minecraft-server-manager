## Reused foundation and implemented behavior

The existing AccessOperationService/Store and authenticated mutation endpoints retain their private append-only intent/checkpoint storage, Manager owner exclusion, cross-restart key replay, and explicit evidence-only recovery. No second journal or authentication system was introduced. Adapter preflight now receives action; apply receives a synchronous authorization callback. Final CAS authorization failure preserves recovery evidence and returns the original fixed authentication denial instead of masking it as HTTP202.

TailscaleControlAdapter has no production CLI implementation. Its construction-only trusted bridge must provide a consistent full snapshot, atomic compare-and-swap with final authorization, and a config/ownership/immutable receipt commit as one unit. No-CAS bridges refuse control. Revisions include daemon epoch and monotonic changes, including external same-shape writes/ABA; a config checksum alone is insufficient.

Enable accepts only exact empty global configuration. Disable accepts only the exact sole HTTPS443 root proxy, matching owned Manager ingress, no Funnel/additional resources, and complete current owning enable receipt. New keys cannot perform no-op enable/disable; existing same-key replay uses the persisted operation. Current configuration, daemon/tailnet/target, previous ownership, root/namespace, revision, action, immutable intent and full pre/post image are revalidated. Any ambiguity preserves evidence and prevents mutation.

Manager identity is derived from the Manager lifetime-lock root identity and the fixed logical access namespace. Physical journal directory identity is bound in receipts; disable additionally compares it to the new intent. Client requests still accept only strict revision/confirm and idempotency header, never target ports, paths or commands.

Observe requires the exact trusted receipt and current head; it never invents operation identity from matching config. Response loss enters recovery_required. Explicit recover only verifies evidence and appends a safe terminal checkpoint; it does not repeat apply, reset Serve, rollback uncertain configuration or remove evidence. Unknown or missing receipts stay blocked.

Control preview combines journal/recovery state and daemon observation under the same Access exclusion. GET /api/v1/access/tailscale/control is authenticated/no-store and exposes only safe status, configuration revision, recovery operation ID and action availability; URL/remoteVerifiedAt remain null. Preview and mutation services must share one coordinator at application construction.

Settings includes explicit preview/confirmation, administrator reauthentication guidance, busy state, stable same-key confirmation after uncertain response, and explicit evidence recovery. It never retries automatically or displays a transport URL. Local management and separate future Cloudflare remain available. The existing read-only card now labels its off value as the startup default, not the observed control state.

## Production boundary

Production defaults to no atomic bridge; control returns TAILSCALE_ATOMIC_CONTROL_UNAVAILABLE and both actions are unavailable. Existing enable/disable endpoints continue ACCESS_UNAVAILABLE before private admission. Fake bridge is imported by tests only and cannot be selected using an HTTP parameter or environment variable.

The target port/identity in Fake tests is an injected manager-ingress model, not a real allocated listener. There is no production remote ingress, reviewed native atomic mutation backend or verified remote URL. This work does not make an installed Tailscale CLI capable of safe CAS. Real daemon/native CLI, phone access, HTTPS transport, external unauthorized-device denial and real enable/disable are NOT RUN / NOT AUTHORIZED. Those require a reviewed deployment design and separate authorization.
