# M2: connected RCON socket process ownership

## Delivered scope

Existing branch `codex/phase-4-players-properties`, baseline HEAD
`d2dadab4c144e5031490e0d2da4b34556524d366`; previous uncommitted M1/M2 retained.
No new supervisor, native writer or general transaction framework.

- `infra/runtime/tcp-peer-owner.ts` uses fixed
  `C:\Windows\System32\netstat.exe -ano -p tcp`, shell=false, hidden window,
  timeout2500ms, maxBuffer256KiB, no interval/continuous polling. Raw system output
  and errors are not logged, persisted or returned. Unknown/missing/duplicate
  tuple, wrong PID/state/address, oversized output and unsupported OS fail closed.
- A verifier inspects the **server side of the actual established connection**:
  local127.0.0.1:RCON-port, remote127.0.0.1:client-ephemeral-port, ESTABLISHED,
  exactly one match with captured owned child PID. A listener snapshot alone or
  the reverse client row cannot prove ownership. Child/lease guards prevent a
  stale OS observation from authorizing a later launch.
- `RconClient` invokes a trusted peer verifier after connect and before reading
  the password or writing AUTH. It bounds the observation by its unchanged
  existing timeout. Verification supplies a synchronous guard for the socket/
  launch; AUTH and command writes recheck it. Each reconnect is freshly checked.
  Verification failure closes only the inspected socket and exposes fixed
  `RCON_PEER_UNVERIFIED`, no raw exception/message/cause. Password-stage failures
  are sanitized and also close the appropriate connection.
- `LocalMinecraftRuntime` always supplies the Windows verifier in production.
  Test-only checker injection is a constructor capability, never HTTP/env input.
  No auto retry, different-instance routing, system changes or stdin fallback.

The OS query is performed per new connection, not per stable authenticated command.
The connected socket cannot be reassigned to a new listening process; runtime
ownership is still checked at each write. This does not certify the game/status
socket, grant cross-Manager port arbitration or eliminate every hostile same-user
OS attack. Existing local authentication/Origin/instance/recovery guards remain.
